# Welcome

Thank you for your interest in contributing to **TestDNA-AI**.

TestDNA-AI is an open-source initiative to build an **AI Operating System for Quality Engineering**—a platform that captures organizational testing knowledge, prevents duplicate automation, and enables intelligent, explainable engineering decisions through AI.

Whether you're a QA Engineer, Software Developer, AI Engineer, DevOps Engineer, Product Designer, Technical Writer, or Student, your contributions are welcome.

---

# Our Mission

We believe every organization should benefit from a continuously growing engineering memory.

Instead of recreating automation from scratch, teams should be able to:

- Discover existing assets
- Reuse proven solutions
- Learn from historical executions
- Understand engineering relationships
- Make AI-assisted quality decisions

Every contribution brings us closer to that vision.

# Repository Structure

```text
testdna-ai/
│
├── apps/
├── packages/
├── services/
├── plugins/
├── sdk/
├── docs/
├── examples/
├── scripts/
├── infrastructure/

```

Contributors should place new functionality in the appropriate module rather than creating unrelated folders.

---

# Branch Naming

Use descriptive branch names.

Examples:

```
feature/dna-engine
feature/search-ranking
feature/neo4j-integration

bugfix/api-timeout
bugfix/search-filter

docs/knowledge-graph
docs/tutorials

refactor/repository-service
```

---

# Commit Message Guidelines

Follow a consistent format.

```
feat: add DNA similarity comparison

fix: resolve repository indexing issue

docs: improve architecture guide

refactor: simplify graph traversal

test: add semantic search tests

chore: update dependencies
```

---

# Coding Standards

General principles:

- Readability over cleverness
- Small, focused functions
- Meaningful naming
- SOLID principles
- Composition over inheritance
- Strong typing where applicable
- Comprehensive error handling

---

# Documentation Standards

Every major feature should include:

- Purpose
- Architecture
- Usage examples
- API references (if applicable)
- Limitations
- Future enhancements

Documentation should evolve alongside the code.

---

# Pull Request Checklist

Before opening a pull request:

- Feature works as expected
- Existing tests pass
- New tests added where appropriate
- Documentation updated
- No sensitive information committed
- Code formatted consistently
- Linting completed

Include:

- Description of the change
- Motivation
- Screenshots (if UI)
- Testing notes
- Related issue

---

# Issue Reporting

A good issue includes:

- Clear title
- Problem description
- Steps to reproduce
- Expected behavior
- Actual behavior
- Environment details
- Screenshots or logs (if available)

This helps maintainers reproduce and resolve issues quickly.

---

# Feature Requests

When proposing a feature, describe:

- The problem it solves
- Current limitations
- Proposed solution
- Expected benefits
- Potential implementation ideas

Focus on user value rather than implementation details alone.

---

# Plugin Contributions

Plugin developers should:

- Follow the Plugin SDK
- Declare permissions
- Include documentation
- Provide tests
- Use semantic versioning
- Avoid unnecessary dependencies

Plugins should extend the platform without compromising stability or security.

---

# AI Contribution Guidelines

AI-related contributions should prioritize:

- Explainability
- Reproducibility
- Evidence-backed reasoning
- Permission-aware retrieval
- Human-in-the-loop workflows

Avoid introducing opaque or unverifiable AI behavior.

---

# Code Review Principles

Reviews should be:

- Respectful
- Constructive
- Specific
- Actionable

Reviewers should explain *why* changes are requested, not just *what* should change.

# Getting Started

If you're new to the project:

1. Read the documentation in the `docs/` directory.
2. Explore the architecture and roadmap.
3. Look for issues labeled **good first issue** or **help wanted**.
4. Ask questions through GitHub Discussions before starting major work.
5. Submit small, focused pull requests to become familiar with the codebase.
